# 演示业务 Brief：把楼层级 IoT 信号变成开店选址能力

## 背景

我们是一家楼层级物理资产防丢失硬件公司，在商场、写字楼和园区部署定位标签、信号采集点和楼层级定位网关。原本这些数据主要用于资产找回、盘点和防丢失预警。

运营一段时间后，我们发现这些数据还反映了一个更通用的问题：不同楼层、不同入口、不同时间段的人流密度、停留时长、复访比例和动线差异。这些信号可能可以转化成面向品牌方、商场运营方和本地商户的“选址与快闪测试”服务。

## 本次希望 Agent 判断的问题

我们想评估是否能将现有楼层级信号数据产品化为“城市快闪店/小店选址建议”服务，并先用一个轻户外品牌周末快闪摊作为试点。

请判断：

- 现有数据是否足以支持初步选址建议；
- 哪些候选点位更适合周末快闪、饮品/轻食、户外小件零售或服务咨询；
- 哪些结论只能作为假设，不能直接承诺给客户；
- 低成本试点应如何设计，才能把方案从 v1 推进到 v2。

## 已知约束

- 预算：第一轮试点预算不超过 3 万元。
- 周期：希望 2 周内完成候选点位筛选，1 个周末完成首轮快闪测试。
- 经营目标：优先验证客流有效性和转化线索，不以首轮利润最大化为唯一目标。
- 数据限制：当前没有完整租约报价、客单价、转化率、天气、节假日活动和商场广告位价格。
- 风险偏好：可以接受中等不确定性，但不能把“高人流”直接等同于“高销售”。

## 希望输出

- 候选点位优先级；
- 每个推荐背后的证据；
- 证据不足导致的降档或保守判断；
- 试点实验设计；
- 下一步需要补充的数据清单；
- v2 迭代时应该关注的指标。
