# FinOps ROI、风险与运营 AI 前端精修设计

## 目标

在不改变 DataForge FinOps 数据契约、MAF 业务流程、认证和生产治理开关的前提下，精修“效能与 ROI”“风险与优化”及运营 AI 的交互。页面必须适合现场演示：层级清楚、无图形重叠、无浮层裁切、AI 弹层立即出现并优先展示已缓存历史。

## 设计方向

采用“克制的企业运营看板”方向，沿用当前颜色、字体、导航和四页信息架构。减少重复解释卡和大面积行动按钮，让数字、证据状态和下一步操作成为主视觉。

## ROI 页面

- 保留一个紧凑的运营判断头部、四项月度测算、价值构成、证据成熟度、单位效能趋势和能力说明。
- 删除页面底部重复的“咨询运营 AI”横幅；头部只保留“调整测算参数”，运营 AI 由全局悬浮按钮承接。
- 指标卡保留小型“问 AI”上下文入口，使用户可以从具体指标发起问题，但不会产生第二套聊天区域。
- 价值构成只显示按正负方向缩放的条形和必要公式信息，不再重复一张与四项指标完全相同的明细表。
- 证据成熟度改为等宽阶段卡，取消穿过文字的连接线；桌面两栏等高，移动端单栏。

## 风险与优化页面

- 保留运营判断、四类风险数量、风险定位、优先事项、优化组合、证据链和治理边界。
- 删除头部“咨询当前判断”和分析说明中的“继续询问”；全局悬浮按钮是唯一聊天面板。
- 风险矩阵不再绘制可能重叠的气泡。按照真实置信度和业务影响将风险放入四象限，每项使用不重叠的紧凑行展示领域、影响范围和真实坐标。
- 优化组合不再使用散点气泡；改为按预期影响排序的横向条形清单，同时显示实施难度与风险领域。
- 选择风险项后继续联动下方证据链，不改变请求证据和整改草案接口。

## 浮层与图表

- 新增统一的视口级 Tooltip。浮层通过 portal 渲染到 `document.body`，使用 `position: fixed`，根据触发元素位置在上/下方选择空间，并将左右位置限制在视口安全边距内。
- 运营指标问号和趋势柱状图复用同一浮层，避免被相邻卡片、`overflow` 或滚动容器裁切。
- 鼠标、键盘焦点和触摸点击均可触发；浮层不承担必须点击的操作。
- 风险象限和优化条形将核心内容直接显示，不依赖 Tooltip 才能理解。

## 运营 AI

- 聊天面板继续使用当前右下角紧凑浮层，不改为抽屉。
- 工作区确定后立即在后台预取最近会话与消息，不再等待用户点击按钮后才开始串行加载。
- 使用工作区内存缓存与请求去重：再次关闭/打开或切换运营页签时立即恢复历史；服务端仍负责 30 天跨设备持久化。
- 打开按钮必须即时渲染面板。预取尚未完成时显示轻量“正在同步历史”，不阻止输入；缓存存在时先显示缓存，再静默更新。
- 清空历史同步清理内存缓存。

## 边界

- 不修改 FinOps API 响应结构、价目表、预算、异常或治理动作。
- 不采集或展示 prompt、completion、密钥、原始身份和内部错误正文。
- `DF_FINOPS_ACTIONS_ENABLED` 保持 `0`。
- 不重新引入 APIM 等基础设施名称。

## 验收

- 1440、1366、1024、390 像素视口下 ROI 和风险页面无重叠、无横向页面溢出。
- 风险和优化项目数与服务端返回一致，所有项目均可选择，真实数值不被视觉排布改写。
- 趋势首列、中间列、末列 Tooltip 均完整位于视口内，并覆盖在相邻卡片之上。
- AI 面板点击后 300ms 内可见；历史请求在打开前已开始；关闭再打开不重复等待网络。
- Node、Vite、完整 Playwright 通过；候选部署健康后完成桌面/移动端生产验收，再切换流量。
