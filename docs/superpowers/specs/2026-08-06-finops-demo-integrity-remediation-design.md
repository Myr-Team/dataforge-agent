# FinOps 演示完整性整改设计

## 背景与目标

当前 FinOps 演示工作区已经具备足够的数据量和差异性，但真实服务端契约、前端展示逻辑与 Playwright mock 之间仍有若干偏差。偏差会造成页面视觉正常、自动化通过，而真实演示出现错误公式、夸大语义、证据不可下钻或 AI 回答与点击项不一致。

本轮目标是在不重构 MAF、FinOps ledger、身份边界和治理动作状态机的前提下，修复已经确认的全部演示完整性缺陷，使运营总览、成本、ROI、风险扫描、证据下钻和运营 AI 形成一条可复核、可解释、可稳定演示的流程。

## 方案选择

### 方案 A：只修前端呈现

通过前端改符号、改文案和扩充 mock，使截图正确。开发量最小，但不能解决真实接口的 ROI 方向、证据类型和 AI 证据范围问题，仍可能在生产演示中失败，因此不采用。

### 方案 B：契约优先的定向修复（采用）

服务端输出明确的 ROI 价值桥方向和授权后的请求级证据引用；前端对风险语义和字符串信号进行封闭映射；AI 仅接收当前指标或风险项允许使用的证据；mock 与演示种子保持同一口径。该方案改动集中、可逐项测试，能够修复真实流程而不扩大治理范围。

### 方案 C：重建统一证据图谱

把 request、run、outcome、artifact 全部抽象成统一证据实体和新查询接口。长期扩展性更强，但会扩大数据库、API 和迁移范围，不符合本次演示整改的时间与风险边界，因此延后。

## 统一原则

- 所有成本继续标记为请求级估算，不声明为 Azure 实际账单。
- ROI 情景参数、运行事实和已验证业务结果继续严格分离。
- 风险扫描保持只读，只生成判断与整改草案，不执行生产变更。
- 客户可见页面不显示 APIM 服务名、内部枚举或原始 provider ID。
- 客户可见证据必须与当前点击的指标、风险规则或 ROI 阶段对应。
- 客户端提供的证据引用不直接受信任；服务端必须与当前租户、工作区、时间窗口和规则重新求交。
- `DF_FINOPS_ACTIONS_ENABLED` 保持关闭；不修改 Easy Auth、Entra 或租户授权边界。

## 1. ROI 价值桥与测算口径

### 服务端契约

`build_roi_decision()` 返回的 `value_bridge.items` 使用明确的公式方向：

- `monthly_benefit`：正向，值为月度收益。
- `monthly_total_cost`：负向，公式展示值为成本绝对值。
- `monthly_net_benefit`：结果项，值为月度净收益。

真实演示种子的标准口径为：

- 月度收益：`3000 USD`
- 实施成本月度摊销：`500 USD`
- 月度固定运营成本：`200 USD`
- 模型成本情景参数：`100 USD`
- AI 运营总投入：`800 USD`
- 月度净收益：`2200 USD`
- ROI：`275%`
- 预计回收周期：约 `2.2 月`

前端仍保留安全回退：即使旧服务未返回 `value_bridge.items`，`monthly_total_cost` 也必须按负向公式项处理。Playwright mock、Node fixture 和后端演示种子统一使用上述值，禁止再用当前请求成本 `0.0269 USD` 替代 ROI 情景中的模型成本 `100 USD`。

## 2. 风险语义与可解释性

现有 `sample_count` 是规则评估的分母样本量，不代表真实受影响请求数；现有 `impact` 是由技术严重度映射的运营优先级，不是已验证业务影响。

客户可见文案统一为：

- “影响范围”改为“评估样本量”。
- “业务影响”改为“运营严重度”。
- “真实影响范围”改为“评估范围”。
- 风险矩阵气泡说明改为“气泡大小代表评估样本量”。
- 优化组合的大小维度显示为“评估样本量”。

后端保留 `sample_count` 和 `impact` 字段以避免无必要的破坏性迁移；`portfolio_metadata.size` 新值使用 `sample_count`，前端兼容旧值 `affected_scope`，但两者都只显示为“评估样本量”。

## 3. 证据信号本地化

前端建立封闭映射，不再把字符串证据信号传给数值转换函数。

允许显示的信号名称至少包括：

- `latency_ms` → 响应时延
- `request_status` → 调用状态
- `pricing_status` → 计价状态
- `cache_state` → 缓存状态
- `gateway_coverage` → 入口治理覆盖
- `tokens_total` → Token 总量
- `estimated_cost` → 估算成本

允许显示的字符串值至少包括：

- `succeeded` / `failed` → 调用成功 / 调用失败
- `hit` / `miss` / `bypassed` / `unavailable` → 缓存命中 / 缓存未命中 / 未使用缓存 / 未记录
- `priced` / `unpriced` / `estimated` → 已计价 / 未计价 / 估算计价
- `apim_governed` / `app_observed` / `unmanaged` / `unknown` → 已纳入统一入口 / 应用侧已观测 / 未纳入统一入口 / 来源待确认

无法识别的字符串不在主卡片直接显示；保留为“暂不可用”，原始值只允许出现在折叠的技术详情中。

## 4. 扫描与决策快照联动

风险扫描成功后必须：

1. 保存最新扫描结果；
2. 失效当前工作区与筛选窗口的风险决策缓存；
3. 重新请求风险决策；
4. 如果原选中风险仍存在则保留选择，否则选择新的第一优先项；
5. 如果决策刷新失败，保留扫描结果并显示“扫描已完成，优先级更新失败”的可重试提示。

扫描不会触发自动治理动作，也不会隐式修改整改草案。

## 5. 运营 AI 的当前项证据约束

### 请求契约

运营 AI 请求增加两个可选的受控字段：

- `policy_type`：仅接受七类已支持风险规则。
- `evidence_refs`：最多三条安全证据引用。

对于风险规则和优先事项，前端发送当前项的 `policy_type` 与 `evidence_refs`；对于普通运营指标，前端发送指标 ID，服务端通过既有 `select_metric_evidence()` 重新选择证据。

### 服务端约束

服务端按照当前授权查询范围重新加载证据：

- 有 `policy_type` 时，调用 `select_policy_evidence()`。
- 普通指标调用 `select_metric_evidence()`。
- 客户端传入的引用与服务端选择结果求交。
- 求交为空时返回 `insufficient_data`，不得回退到整个查询窗口的前 50 条请求。
- AI 输出仍只能引用服务端允许的证据，并继续隐藏原始证据 ID。

这样“问 AI”生成的问题、AI 回答和“查看证据”打开的内容共享同一证据集合。

## 6. ROI 阶段证据下钻

本轮不新增通用证据图谱接口。服务端在构建 ROI 决策时，把 `run-*` 和 `outcome-*` 通过当前工作区、当前窗口内的运行与请求关系投影为授权后的 `req_*` 引用：

- 投入阶段使用已计价请求引用。
- 使用阶段使用当前运行对应的请求引用。
- 产出阶段使用生成这些产物的运行对应请求引用。
- 业务结果阶段使用 outcome source run 对应的请求引用。

无法找到请求映射时保留证据数量和缺口说明，但不生成不可点击的伪入口。前端继续通过现有请求详情抽屉展示业务请求、响应摘要、模型、缓存、成本、时延和技术引用。

## 7. FinOps/ROI AI 模型路由

将以下 Agent 纳入工作区模型策略允许列表：

- `df-finops-analyst`
- `df-roi-analyst`

运营 AI、FinOps 分析和 ROI 分析在调用模型前加载当前 workspace 的模型策略与价目卡，并以对应 Agent ID 选择 `full_analysis` 路由。演示工作区默认配置：

- 主路由：`terra`
- 回退路由：现有 `analysis` 路由

如果 Terra 未进入服务端 allowlist、能力不匹配或运行时关闭，则使用既有安全回退并在内部遥测记录原因；前端不得虚假显示“由 Terra 执行”。模型切换继续使用现有 `base_revision` 乐观并发与审计持久化。

## 8. 性能与错误处理

- 不增加周期性刷新频率；可见决策页继续使用十分钟刷新窗口和页面隐藏暂停。
- 风险扫描只在用户点击后增加一次决策刷新，不引入轮询。
- AI 证据最多三条，避免扩大请求与模型上下文。
- 缓存命中时继续先展示最近成功数据，再进行后台更新。
- 任何更新失败都保留最后一次成功数据并提供局部重试，不回退为整页空白。

## 9. 测试与验收

每项修复必须遵循失败测试先行：

1. 后端单元测试验证价值桥方向、风险元数据、ROI 请求映射、AI 证据交集和 Terra Agent 路由。
2. Node 测试使用真实服务端形状验证 ROI 减法、字符串信号中文显示和风险语义。
3. API 契约测试验证客户端伪造或越权证据会被丢弃，空交集返回 `insufficient_data`。
4. Playwright 验证扫描后优先级刷新、不同风险的证据与 AI 回答一致、ROI 阶段证据可打开、桌面与移动端无覆盖。
5. mock 与 `demo_workspace_seed` 的 ROI 参数和六类风险证据逐项对齐。
6. 运行全量 Python、Node、Vite build 和隔离端口 Playwright。
7. 部署零流量 backend/web candidate 后，使用登录态在真实 `demo-corpus` 完成：总览 → 成本 → ROI → 风险扫描 → 证据 → AI → 返回页面。
8. 验收首屏骨架、缓存回显、局部失败重试、页面刷新和三到五分钟运营数据刷新策略。
9. 生产切流前人工确认；未经用户明确批准不合并主线、不切生产流量。

## 非本轮范围

- Azure Cost Management 实际账单对账。
- 自动批准或执行生产治理动作。
- 新建通用证据图数据库或跨服务证据总线。
- 对所有 MAF Agent 的模型策略进行重新设计。
- 修改 Entra 身份、Easy Auth、工作区授权或审计保留规则。
