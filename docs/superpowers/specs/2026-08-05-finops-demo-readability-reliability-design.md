# FinOps 演示可读性与加载可靠性设计

## 目标

在不改变 MAF、权限边界、生产治理开关和 FinOps 数据口径的前提下，修复生产首屏等待、运营 AI 参数校验失败，以及 ROI、风险治理页面难以解释的问题。交付必须同时改善实际加载可靠性与演示时的视觉可读性，不能用静态前端数值掩盖接口缺失。

## 范围

本次包含四项相互独立但共同验收的改动：

1. 工作区 Dashboard 短时进程内缓存、并发防击穿以及明确的加载/失败/重试状态。
2. 运营 AI 指标上下文归一化、用户友好错误、结构化五段回答和历史记录即时展示。
3. ROI 价值构成由左右半轴改为“收益 − 投入 = 净收益”的公式流，ROI 与回收期作为结果指标单独展示。
4. 风险治理证据区由五等分长文本改为“判断摘要、完整建议、代表证据”三层结构。

本次不修改 Easy Auth、Entra 权限判断、模型路由、价目表、治理执行开关、自动整改或生产流量。

## 加载可靠性

Dashboard 缓存按 `workspace_id` 隔离，默认 TTL 为 2 秒并允许通过 `DF_DASHBOARD_CACHE_SECONDS` 调整。过期时间必须在聚合成功后使用单调时钟计算；失败结果不得缓存。并发控制采用按工作区 single-flight，同一工作区的冷请求复用一次聚合，不同工作区之间不得被全局锁串行阻塞。

缓存返回值必须与内部缓存对象隔离，调用方修改嵌套列表或字典不能污染后续响应。过期条目在读写时清理，并设置有限容量，避免长期运行积累无效工作区键。

前端首屏明确区分三种状态：加载中显示骨架；成功后显示真实 Dashboard；失败时显示正文错误说明和“重新加载”按钮。错误后不得永久停留在骨架。运营管理在权限和工作区作用域已就绪时可以独立加载，不再等待 Dashboard 聚合完成。

## 运营 AI

前端在发起请求前将指标的完整度与证据状态分开处理：

- `data_status` 只发送 `complete`、`partial`、`unavailable` 或 `insufficient_data`。
- `evidence_state` 只发送 `observed`、`estimated`、`partial` 或 `unavailable`。
- `estimated` 指标映射为 `data_status=partial`、`evidence_state=estimated`，保留“情景估算”含义且满足后端契约。

HTTP/Pydantic 校验详情不得作为聊天正文展示。请求失败时显示简短的“当前分析未完成，请重试”，并提供重试操作；技术详情保留在开发日志，不写入跨设备历史。

成功回答优先显示五段结构：结论、依据、影响、建议、判断边界。旧历史只有纯文本时按段落展示，限制单行宽度并保留自然换行。点击任一指标的“问 AI”继续自动携带该指标、筛选范围和时间窗口；历史缓存先即时回显，再在后台同步服务端记录。

## ROI 价值构成

取消以中线区分正负方向的四条同构条形图，因为现有四项并非同一单位且左侧灰区不代表实际数值。

采用公式流布局：

`月度收益 − AI 运营总投入 = 月度净收益`

三个金额卡使用同一 USD 口径，投入以减项颜色和符号表达，净收益作为结果高亮。ROI 比率和预计回收期放入独立结果区，不再与 USD 金额共享比例尺。每项继续显示问号解释、情景测算/已验证状态及服务端返回值；缺失值保持“未记录”或“暂不可用”。桌面保持一行公式，窄屏改为纵向流程。

## 风险治理证据区

选中风险后展示三层信息：

1. 判断摘要：风险名称、领域、影响请求数、证据数量和当前状态。
2. 完整建议：完整展示服务端建议与预计影响，不使用省略号截断；“问 AI”和“查看整改方案”与当前风险上下文绑定。
3. 代表证据：请求证据卡片保留两列桌面布局和单列移动布局，技术字段默认收起；查看证据、确认异常、抑制异常保持原权限与状态逻辑。

原有“信号—影响范围—代表证据—建议—改善验证”语义压缩为短标签进度条，仅承担流程导航，不再承载长文本。任何推荐都不能被描述为已执行或已完成改善。

## 视觉方向与响应式

沿用现有 DataForge 冷静、简洁的企业运营风格：白色表面、低饱和蓝色主操作、橙色估算提示、绿色已验证状态。减少重复边框与大面积空白，通过字体层级和间距建立信息关系，不新增渐变装饰或无意义图标。

桌面验收宽度为 1440px，移动验收宽度为 390px。所有文本不得重叠或被相邻卡片裁切；Tooltip 使用视口定位；AI 面板建议按钮允许自然换行或受控横向滚动，页面本身不得产生横向滚动条。

## 测试与验收

后端测试必须覆盖：慢聚合后仍命中 TTL、同工作区并发只构建一次、不同工作区并行、嵌套值修改不污染缓存、失败不缓存、过期清理与容量边界。

前端单元测试必须覆盖：`estimated` 上下文归一化、技术错误转为友好文案、ROI 公式流字段与状态、风险建议不截断。

Playwright 必须覆盖：Dashboard 延迟后骨架替换、Dashboard 失败后出现可重试状态、运营管理不等待 Dashboard、AI 指标提问不再返回校验 JSON、ROI 与风险页面在 1440px 和 390px 无遮挡。最终执行全量 Python、Node、Vite build、Playwright 和 `git diff --check`，并保存桌面及移动端验收截图。
