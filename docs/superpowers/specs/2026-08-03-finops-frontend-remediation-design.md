# FinOps 前端决策优先精修设计

## 背景

当前运营管理的接口契约和自动化回归均正常，但页面仍存在三个演示风险：成本分析重复展示同一归因结果，风险与优化把七条规则放在决策内容之前，移动端与部分图表中的小字号、浮层和悬浮 AI 会削弱可读性。本轮不扩展能力边界，只重新组织已有信息，使 IT 与财务受众先看到结论、影响和下一步。

## 目标与非目标

目标：

- 让成本、ROI、风险三个页面分别回答一个明确问题。
- 保留所有真实数据状态、证据下钻和上下文 AI 能力。
- 桌面与移动端均能在首屏附近看到主要结论与决策入口。
- 减少重复图表，修复 tooltip、悬浮按钮和过小文字造成的阅读问题。

非目标：

- 不修改后端、API、认证、Easy Auth 或生产配置。
- 不新增模拟接口数据，不把缺失值伪装成已观测数据。
- 不合并、不部署、不切换生产流量。
- 不在本轮处理主应用 bundle 拆分或依赖升级。

## 信息架构

### 运营总览

保持现有四个 KPI、成本与调用趋势、部门成本结构和关注事项。该页已经承担“当前发生了什么”的高管摘要，不再增加明细组件。

### 成本分析

页面回答“钱花在哪里，以及谁需要进一步核查”。保留：

1. 成本趋势和可用性说明。
2. 部门与工作区归因表。
3. Agent 和模型成本排名。

移除页面底部与排名含义重复的 Agent/模型成本结构环形图。部门结构已经在总览表达，成本页不再追加同类构成图。

### 效能与 ROI

页面回答“投入是否形成可验证价值”。保留现有判断横幅、四个测算指标、价值桥和证据成熟度。只调整字号、间距、状态标签和移动端换行，不重新定义 ROI 口径。

### 风险与优化

页面回答“现在应优先处理什么”。顺序调整为：

1. 本期风险判断与扫描摘要。
2. 风险域汇总。
3. 风险矩阵和优先事项。
4. 当前选中风险的证据链。
5. 风险组合及治理说明。

七条扫描规则保留，但放入默认收起的“判定规则”披露区。扫描按钮、最近扫描时间、覆盖请求数和命中数始终可见；用户需要解释规则时再展开，避免规则清单占据决策内容之前的多屏空间。

## 交互与视觉

- 支持文本的最小目标字号为 11px，主要正文使用 12px，标题使用 13–16px。
- 风险规则使用原生可访问披露控件，键盘可展开，并提供规则总数和异常数摘要。
- 图表 tooltip 继续使用视口边界定位，桌面和 390px 移动端均不得被相邻卡片或视口裁切。
- 运营 AI 仍为右下角悬浮入口；FinOps 页面为其预留安全区，避免遮住最后一行指标或图表标签。
- 不把 AI 改成常驻侧栏。上下文按钮继续携带当前指标、风险或证据引用。

## 数据与状态

- 本轮复用现有 API 和 view model，不改变字段或刷新策略。
- `available`、`partial`、`unavailable`、`estimated` 等状态原样保留。
- 风险规则折叠仅改变呈现，不影响扫描、选择、证据绑定和 AI 上下文。
- 删除重复图表不删除对应数据请求；如确认请求只服务于被删除视图，再通过测试证明后取消前端读取。

## 验收

- Node 测试保护成本页不再重复渲染结构图，并保护风险规则默认折叠。
- Playwright 验证桌面与移动端的决策内容顺序、规则展开、tooltip 边界和悬浮 AI 安全区。
- Python、Node、Vite、Playwright 全量回归通过。
- 输出总览、成本、ROI、风险的桌面与移动端截图。
- 仅创建 GitHub PR，生产仍保持当前 revision 与流量不变。
