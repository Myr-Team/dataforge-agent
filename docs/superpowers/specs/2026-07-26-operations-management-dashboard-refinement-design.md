# DataForge 运营管理 Dashboard 收敛设计

## 目标

在不改变 MAF、分析流程和业务内核的前提下，把现有 FinOps Portal 收敛为面向 IT 与财务人员的“运营管理”Dashboard。页面应在首次进入和刷新时结构稳定、信息直观，并保留会话、运行记录和产物各自清晰的职责。

## 已确认问题

1. 左侧“运营治理”和“系统”依赖异步能力接口，导致它们晚于“业务工作台”出现。
2. `.finops-head > div > span` 同时命中了说明文字和右上角状态文字，造成“数据更新中”错位。
3. 长时间打开页面后，Easy Auth 登录会话过期，后台请求被重定向到微软登录页，浏览器最终只暴露 `Failed to fetch`。当前页面将该错误直接作为全局错误展示。
4. 工作区“自动分析”复用了普通会话发送函数，无条件把系统代发问题加入前端消息列表。
5. `RunsCenter` 与 `runs` 路由仍然存在，但左侧导航移除了“运行记录”入口。
6. 左侧底部 Workspace、Role 和 Invite members 区域占用空间，并与顶部工作区切换和设置页重复。
7. 当前 FinOps/ROI Agent 卡片占据主要 Dashboard 区域，削弱了指标、分解和趋势的主导地位。

## 导航与职责边界

左侧导航始终同步渲染，不等待工作区或治理能力接口：

- 业务工作台
  - 工作区
  - 数据资产
  - 会话
  - 运行记录
  - 分析产物
- 运营管理
  - 运营管理
- 系统
  - 设置

能力接口只决定目标页面能否读取数据，不决定导航节点是否存在。权限尚未返回时，点击运营管理展示局部加载状态；权限不足时展示明确的无权访问页面。所有真实授权仍由后端执行。

删除左侧底部 Workspace、Role 和 Invite members。工作区名称继续由顶部切换器承载；成员与权限管理入口移入设置页。

## 运营管理信息架构

页面名称统一为“运营管理”，采用“总览判断 → 专题分析 → 证据下钻”的三级信息架构。所有能力均纳入，但不同时堆在首页：

1. 运营总览：调用、Token、估算成本、P50/P95、错误率、缓存命中率、APIM 覆盖率、预算状态。
2. 成本与预算：成本趋势、预算消耗、模型成本分布、Agent 成本分布、部门与工作区分摊、预算预测和分项明细。
3. 效能与 ROI：任务完成量、单位任务成本、单位分析成本、单位产物成本、已验证收益、ROI 状态、证据完整度和趋势。
4. 风险与优化：异常、慢请求、未计价请求、治理覆盖缺口、优化建议和审批动作。

首页只放跨角色共同需要的关键判断；预算预测、分摊、ROI 证据、请求明细和治理动作放在对应页签的专题区或下钻层。IT 默认看到可靠性、性能和覆盖率，财务默认看到成本、预算和 ROI；二者使用同一事实口径，不创建两套数据。

借鉴 OptScale 的“摘要指标 + 日期范围 + 趋势图 + 分布饼图 + 明细表”组合方式，但不复制其组件或代码：

- 成本与预算增加“模型成本构成”和“Agent 成本构成”环形图。
- 运营总览增加“Token 构成”环形图，区分输入、输出、缓存和推理 Token。
- 效能与 ROI 使用价值来源构成图；只显示有证据的构成项。
- 分类不足两个或合计为零时不绘制饼图，改用明确的空状态。
- 同一维度在环形图、趋势图和明细表中使用稳定一致的颜色。
- 图表与明细联动，点击分区只改变当前筛选，不触发生产治理动作。
- 指针悬停或键盘聚焦数据点时，以 160–220ms 的过渡高亮当前项并适度弱化其他项；动画遵循系统“减少动态效果”设置。
- 图表提示框统一显示指标名称、当前值、占比或环比、时间窗口、数据状态和证据状态。
- 只有缓存相关数据具备真实记录时，提示框才显示“缓存命中”“缓存未命中”“绕过缓存”或“缓存状态不可用”，不得根据延迟或成本猜测缓存状态。
- 提示框提供“问 AI”入口，将当前数据点作为聊天上下文。

Dashboard 不生成示例数字；缺失值使用“未记录”“证据不足”或“暂不可用”。

## 指标交互与决策增强

每个图表和指标都应成为可解释、可联动、可追问的决策对象：

- 指标悬浮卡按指标类型展示字段，不使用一套泛化模板：
  - Token：输入、输出、缓存输入、推理、总量和构成比例。
  - 缓存：命中、未命中、绕过、不可用和 eligible 样本数。
  - 成本：金额、币种、计价状态、价格版本、已计价与未计价请求。
  - 调用与质量：成功、4xx、5xx、P50、P95、样本量和错误类别。
  - Agent 与模型：调用、成功率、Token、估算成本、P95 和主要路由。
- 点击部门、工作区、人员、Agent、模型或状态后，其他图表和明细同步过滤；页面顶部展示可删除的筛选标签，并提供“一键重置”。
- URL 保存非敏感筛选条件，刷新或分享链接后恢复同一分析视图；workspace 和 tenant 范围仍由服务端授权收窄。
- 支持“上一等长周期”对比，展示绝对变化、变化率和主要贡献来源；无可比数据时明确显示“暂无对比基线”。
- 趋势图允许标记异常、预算阈值、价格版本切换、策略变更和治理动作；悬浮标记可查看时间、影响范围和证据链接。
- 每张卡片独立展示数据状态与最后同步时间，避免一个全局状态掩盖局部过期或部分失败。
- 下钻路径保持一致：汇总指标 → 维度分解 → 请求证据 → Foundry Trace。客户界面优先展示“工作区名称 + 操作类型 + 时间”的业务名称，内部 ID 仅在详情中提供复制。
- 悬浮不是唯一入口；键盘聚焦、移动端点击和辅助技术均能读取相同提示内容。

## 成本、预算与分摊

完整 FinOps 能力基于 DataForge 估算成本账本，不冒充 Azure 实际账单：

- 预算可按组织、部门、工作区、Agent 或模型配置月度金额和 warning/critical 阈值。
- 预算燃烧展示已使用、剩余、周期进度和按当前速率计算的期末预测；预测必须显示“基于估算成本”及置信状态。
- 成本分摊遵循 tenant → department → workspace 的唯一归属关系；未映射 workspace 进入“未归属”，不得重复分摊。
- 支持按调用量、Token、估算成本和单位成果成本查看 showback；本期不生成财务记账凭证，也不进行自动 chargeback。
- 价目表 revision、未计价比例、币种和数据覆盖率在分项明细中始终可追溯。
- 提供 IT 视图、财务视图和自定义保存视图；保存内容仅包括筛选、列、排序和图表偏好，不保存数据副本。
- 支持导出当前授权范围内的 CSV 和打印友好报告；导出继承页面筛选、字段脱敏和服务端权限。

## 效能与 ROI

ROI 不只展示一个比例，而是展示可审计的证据链：

- 证据漏斗固定为“投入 → 使用 → 产出 → 业务结果”。
- 投入包括估算模型成本和可配置的人工/平台成本；使用包括调用、活跃工作区和任务；产出包括成功分析和有效产物；业务结果只接受已验证价值事件。
- 依次提供“每次成功调用成本”“每次成功分析成本”“每个有效产物成本”；分母为零或口径不完整时不计算。
- ROI 只有在投入和收益证据均完整时给出已验证值；否则显示“证据不足”并列出缺失环节。
- 趋势和构成图可以下钻到价值事件、关联产物和运行记录，但不展示原始 prompt 或响应正文。
- 支持在不写入生产配置的前提下进行情景比较，例如模型替换、缓存命中率变化或调用增长对估算成本的影响；所有结果明确标记为“情景测算”。

## 风险与优化工作台

风险与优化不展示孤立的告警列表，而是提供按影响、证据和处置成本排序的机会队列：

- 每项机会显示预计影响、置信度、实施难度、证据覆盖、受影响范围和建议动作。
- 支持按成本节省、可靠性、缓存、治理覆盖和未计价风险分类。
- 异常可从趋势标记、指标悬浮卡或列表进入同一详情，避免产生三套对象。
- AI 可以解释、比较和生成治理草案；批准、执行、验证和回滚继续遵循已有审批状态机。
- 推荐项只有具备足够样本和可复核证据时才进入机会队列；否则进入“观察中”，不计算预期节省。

## 数据与接口增量

现有 `/api/finops/bootstrap`、filters、overview、breakdowns、trends、requests、anomalies、recommendations、actions 和 insights 接口继续保留。新增能力优先扩展现有聚合响应，只有具备独立生命周期的数据才增加接口：

- 预算：预算定义、使用进度、阈值和期末预测。
- 保存视图：名称、角色模板、筛选、列、排序和图表偏好。
- ROI 价值事件：事件类型、金额或非金额价值、证据状态、关联 workspace/run/artifact 和验证信息。
- 情景测算：只读输入、计算假设、基线、测算结果和数据状态，不写入模型路由或缓存策略。
- 导出：服务端创建当前 scope 的短期导出任务，返回安全下载结果；客户端不得导出未加载或未授权数据。

所有聚合响应继续包含 `scope/window/freshness/coverage/currency/data_status`。新增数值必须同时返回口径、证据状态和可比基线；预算、预测、ROI 和节省估算不得只返回一个无解释数字。

## 交付切片

“全部纳入”不等于一次性向客户暴露未完成能力。实施和验收按以下切片推进，每一片都保持可运行：

1. 外壳与可靠性：同步导航、登录失效恢复、预取、稳定骨架、局部错误、运行记录和隐藏自动分析指令。
2. 决策交互：指标专属提示、动效、跨图联动、筛选恢复、同期对比、事件标记和轻量 AI 浮框。
3. 成本与预算：预算定义、燃烧率、估算预测、部门/workspace 分摊、保存视图和导出。
4. 效能与 ROI：单位经济指标、证据漏斗、价值事件和只读情景测算。
5. 风险与闭环：机会队列、治理草案、审批、候选执行、验证和回滚。

切片 3–5 的页面可以随代码部署，但在数据迁移、权限和验收完成前保持能力开关关闭；不使用示例数据伪装已上线。

## Agent 辅助定位

FinOps 和 ROI 不再以 Agent 卡片或整块侧栏作为主要内容。页面右侧固定一个轻量 AI 按钮；点击后从按钮位置挂接一个小型聊天框，不覆盖整列 Dashboard，也不改变主内容宽度。

聊天框支持：

- 直接询问当前页签的成本、预算、效能、ROI、风险和优化问题。
- 从指标卡、图表数据点或表格行的“问 AI”入口打开，并自动关联所选指标。
- 显示当前关联对象，例如“正在询问：缓存命中率 · 最近 30 天 · 当前工作区”。
- 根据上下文提供“为什么变化”“是否异常”“主要贡献来源”“如何优化”等快捷问题，但不替用户自动发送。
- 允许用户清除指标上下文后继续一般运营问答。
- 返回基于已加载证据的口径说明、变化解读、优化建议和证据强弱。
- 提供“查看证据”链接；创建治理草案仍使用明确的独立确认操作。

每个可询问对象提供统一的 `MetricContext`：

- `metric_id`：稳定的内部指标标识。
- `label`、`value`、`unit`：客户可见名称、当前值和单位。
- `dimension`、`dimension_value`：模型、Agent、部门、工作区或缓存状态等分解上下文。
- `window`、`filters`：当前时间窗口和筛选范围。
- `data_status`、`evidence_state`：数据完整性和证据状态。
- `cache_state`：仅在接口实际返回时使用。

前端只向分析接口发送上述安全上下文，不发送图表 DOM、整页内容或任意资源 ID。Agent 不得替代 Dashboard 指标，不得补造成本或 ROI，不得批准或执行治理动作。聊天失败不影响 Dashboard 数据展示。

## 加载、预取与错误恢复

1. 应用外壳、完整导航和页面标题同步渲染。
2. 登录身份和工作区确定后，在浏览器空闲时预取运营管理 bootstrap。
3. 进入运营管理时优先使用 60 秒内缓存；后台更新成功后替换。
4. 更新失败但存在缓存时保留现有数据，并显示“上次同步 HH:mm”与局部告警。
5. 页面按组件隔离错误，单个图表或明细接口失败不得清空整个 Dashboard。
6. 请求出现网络失败时检查登录状态；确认会话失效后显示“登录已失效，请刷新后重新登录”，不再向客户展示英文 `Failed to fetch`。
7. 右上角状态统一为“同步中”“已同步 HH:mm”或“同步失败”，状态文字与刷新按钮使用独立选择器和垂直居中布局。
8. 60 秒自动刷新只在页面可见且登录有效时执行；同一 scope 的进行中请求继续去重。
9. 骨架屏与最终组件使用相同尺寸，禁止因数据返回导致导航、卡片或图表整体跳动。
10. 预取按“总览优先、专题延后”执行；预算预测、分摊明细和请求证据不阻塞首屏关键指标。

## 自动分析与会话

工作区“自动分析”继续使用现有分析内核，但以隐藏系统指令启动：

- 不把系统代发问题加入 `messages`。
- 不创建或恢复客户可见会话。
- 后端请求保持 `origin=workspace_auto_analysis` 和 `persist_messages=false`。
- 任务中心与运行记录继续显示分析任务状态和 Agent 执行步骤。
- 用户手动输入的问题维持现有会话行为。

历史会话加载时过滤已经存在的同一条系统代发问题，避免旧数据再次显示；不得过滤用户手动输入的相似自然语言问题。

## 运行记录

恢复独立“运行记录”入口，复用现有 `RunsCenter`：

- 展示运行状态、时间、触发来源、参与 Agent 和关键步骤。
- 支持打开运行详情和回到关联会话。
- 自动分析即使不进入会话，也保留运行记录。
- 运行记录只展示安全摘要，不暴露 prompt、密钥、原始身份或内部错误正文。

## 测试与验收

### 自动化

- 导航契约测试：能力接口未返回时完整导航已存在。
- 自动分析测试：启动后消息列表不出现系统代发问题；请求 origin 与持久化标志正确。
- 历史会话测试：只过滤精确的旧系统代发问题。
- 运行记录测试：入口可见并能打开现有 `RunsCenter`。
- FinOps 加载测试：缓存更新失败保留数据；登录失效展示中文提示；组件部分失败不升级为全局失败。
- 图表测试：零值、单分类、多分类、稳定颜色、筛选联动、悬停/聚焦高亮和减少动态效果。
- 图表提示测试：不同指标展示各自字段和正确口径；没有真实缓存字段时不显示缓存命中结论。
- 对比与标记测试：等长周期计算、无基线状态、异常/预算/价格/策略事件定位正确。
- 分摊与预算测试：唯一归属、未归属、阈值、燃烧率和期末预测不重复计算，且始终标记为估算。
- ROI 测试：单位经济分母为零、证据缺失、已验证收益和情景测算状态正确。
- 保存视图与导出测试：只保存安全偏好；刷新恢复；导出继承当前授权、筛选和脱敏规则。
- AI 浮框测试：按钮打开挂接聊天框且不改变 Dashboard 宽度；从指标打开时携带正确 `MetricContext`；清除上下文后不再发送指标信息。
- CSS/DOM 契约测试：同步状态和刷新按钮在同一容器内居中，不受标题说明选择器影响。

### 浏览器

- 桌面端和移动端首次进入截图。
- 强制刷新后立即检查完整导航，不允许运营管理或系统后出现。
- 进入运营管理时检查预取命中、加载骨架、同步状态和图表布局。
- 通过鼠标、键盘和移动端点击检查图表数据点动效、指标专属提示框、跨图联动和“问 AI”指标关联。
- 检查 AI 聊天框在桌面和移动端均从按钮附近展开，不以整块右侧抽屉挤压 Dashboard。
- 检查同期对比、事件标记、预算预测、成本分摊、ROI 证据漏斗、保存视图和导出。
- 模拟 bootstrap、明细接口和登录失效三类错误。
- 启动自动分析，确认会话中无系统代发问题，运行记录中有对应任务。
- 从运行记录回到关联会话。

### 部署

- Python、Node、Vite 和 Playwright 全量回归通过。
- backend/web 先部署零流量候选 revision。
- 候选环境完成桌面、移动端、强制刷新、登录失效和真实接口验收。
- 保留当前生产 revision 作为回滚目标。
- 验收完成后才切换生产流量；治理执行开关继续保持关闭。

## 非目标
