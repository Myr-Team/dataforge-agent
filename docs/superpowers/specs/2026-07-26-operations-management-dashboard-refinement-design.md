# DataForge 运营管理 Dashboard 收敛设计

## 目标

在不改变 MAF、分析流程和业务内核的前提下，把现有 FinOps Portal 收敛为面向 IT 与财务人员的“运营管理”Dashboard。页面应在首次进入和刷新时结构稳定、信息直观，并保留会话、运行记录和产物各自清晰的职责。

## 已确认问题

1. 左侧“运营治理”和“系统”依赖异步能力接口，导致它们晚于“业务工作台”出现。
2. `.finops-head > div > span` 同时命中了说明文字和右上角状态文字，造成“数据更新中”错位。
3. 长时间打开页面后，Easy Auth 登录会话过期，后台请求被重定向到微软登录页，浏览器最终只暴露 `Failed to fetch`。当前页面将该错误直接作为全局错误展示。
4. 工作区“自动分析”复用了普通会话发送函数，无条件把系统代发问题加入前端消息列表。
5. `RunsCenter` 与 `runs` 路由仍然存在，但左侧导航移除了“运行记录”入口。
6. 左侧底部 Workspace、Role 和 Invite members 区域占用空间，并与顶部工作区切换和设置页重复。
7. 当前 FinOps/ROI Agent 卡片占据主要 Dashboard 区域，削弱了指标、分解和趋势的主导地位。

## 导航与职责边界

左侧导航始终同步渲染，不等待工作区或治理能力接口：

- 业务工作台
  - 工作区
  - 数据资产
  - 会话
  - 运行记录
  - 分析产物
- 运营管理
  - 运营管理
- 系统
  - 设置

能力接口只决定目标页面能否读取数据，不决定导航节点是否存在。权限尚未返回时，点击运营管理展示局部加载状态；权限不足时展示明确的无权访问页面。所有真实授权仍由后端执行。

删除左侧底部 Workspace、Role 和 Invite members。工作区名称继续由顶部切换器承载；成员与权限管理入口移入设置页。

## 运营管理信息架构

页面名称统一为“运营管理”，保留四个一级页签：

1. 运营总览：调用、Token、估算成本、P50/P95、错误率、缓存命中率、APIM 覆盖率、预算状态。
2. 成本与预算：成本趋势、预算消耗、模型成本分布、Agent 成本分布和分项明细。
3. 效能与 ROI：任务完成量、单位任务成本、已验证收益、ROI 状态、证据完整度和趋势。
4. 风险与优化：异常、慢请求、未计价请求、治理覆盖缺口、优化建议和审批动作。

借鉴 OptScale 的“摘要指标 + 日期范围 + 趋势图 + 分布饼图 + 明细表”组合方式，但不复制其组件或代码：

- 成本与预算增加“模型成本构成”和“Agent 成本构成”环形图。
- 运营总览增加“Token 构成”环形图，区分输入、输出、缓存和推理 Token。
- 效能与 ROI 使用价值来源构成图；只显示有证据的构成项。
- 分类不足两个或合计为零时不绘制饼图，改用明确的空状态。
- 同一维度在环形图、趋势图和明细表中使用稳定一致的颜色。
- 图表与明细联动，点击分区只改变当前筛选，不触发生产治理动作。
- 指针悬停或键盘聚焦数据点时，以 160–220ms 的过渡高亮当前项并适度弱化其他项；动画遵循系统“减少动态效果”设置。
- 图表提示框统一显示指标名称、当前值、占比或环比、时间窗口、数据状态和证据状态。
- 只有缓存相关数据具备真实记录时，提示框才显示“缓存命中”“缓存未命中”“绕过缓存”或“缓存状态不可用”，不得根据延迟或成本猜测缓存状态。
- 提示框提供“问 AI”入口，将当前数据点作为聊天上下文。

Dashboard 不生成示例数字；缺失值使用“未记录”“证据不足”或“暂不可用”。

## Agent 辅助定位

FinOps 和 ROI 不再以 Agent 卡片或整块侧栏作为主要内容。页面右侧固定一个轻量 AI 按钮；点击后从按钮位置挂接一个小型聊天框，不覆盖整列 Dashboard，也不改变主内容宽度。

聊天框支持：

- 直接询问当前页签的成本、预算、效能、ROI、风险和优化问题。
- 从指标卡、图表数据点或表格行的“问 AI”入口打开，并自动关联所选指标。
- 显示当前关联对象，例如“正在询问：缓存命中率 · 最近 30 天 · 当前工作区”。
- 允许用户清除指标上下文后继续一般运营问答。
- 返回基于已加载证据的口径说明、变化解读、优化建议和证据强弱。
- 提供“查看证据”链接；创建治理草案仍使用明确的独立确认操作。

每个可询问对象提供统一的 `MetricContext`：

- `metric_id`：稳定的内部指标标识。
- `label`、`value`、`unit`：客户可见名称、当前值和单位。
- `dimension`、`dimension_value`：模型、Agent、部门、工作区或缓存状态等分解上下文。
- `window`、`filters`：当前时间窗口和筛选范围。
- `data_status`、`evidence_state`：数据完整性和证据状态。
- `cache_state`：仅在接口实际返回时使用。

前端只向分析接口发送上述安全上下文，不发送图表 DOM、整页内容或任意资源 ID。Agent 不得替代 Dashboard 指标，不得补造成本或 ROI，不得批准或执行治理动作。聊天失败不影响 Dashboard 数据展示。

## 加载、预取与错误恢复

1. 应用外壳、完整导航和页面标题同步渲染。
2. 登录身份和工作区确定后，在浏览器空闲时预取运营管理 bootstrap。
3. 进入运营管理时优先使用 60 秒内缓存；后台更新成功后替换。
4. 更新失败但存在缓存时保留现有数据，并显示“上次同步 HH:mm”与局部告警。
5. 页面按组件隔离错误，单个图表或明细接口失败不得清空整个 Dashboard。
6. 请求出现网络失败时检查登录状态；确认会话失效后显示“登录已失效，请刷新后重新登录”，不再向客户展示英文 `Failed to fetch`。
7. 右上角状态统一为“同步中”“已同步 HH:mm”或“同步失败”，状态文字与刷新按钮使用独立选择器和垂直居中布局。
8. 60 秒自动刷新只在页面可见且登录有效时执行；同一 scope 的进行中请求继续去重。

## 自动分析与会话

工作区“自动分析”继续使用现有分析内核，但以隐藏系统指令启动：

- 不把系统代发问题加入 `messages`。
- 不创建或恢复客户可见会话。
- 后端请求保持 `origin=workspace_auto_analysis` 和 `persist_messages=false`。
- 任务中心与运行记录继续显示分析任务状态和 Agent 执行步骤。
- 用户手动输入的问题维持现有会话行为。

历史会话加载时过滤已经存在的同一条系统代发问题，避免旧数据再次显示；不得过滤用户手动输入的相似自然语言问题。

## 运行记录

恢复独立“运行记录”入口，复用现有 `RunsCenter`：

- 展示运行状态、时间、触发来源、参与 Agent 和关键步骤。
- 支持打开运行详情和回到关联会话。
- 自动分析即使不进入会话，也保留运行记录。
- 运行记录只展示安全摘要，不暴露 prompt、密钥、原始身份或内部错误正文。

## 测试与验收

### 自动化

- 导航契约测试：能力接口未返回时完整导航已存在。
- 自动分析测试：启动后消息列表不出现系统代发问题；请求 origin 与持久化标志正确。
- 历史会话测试：只过滤精确的旧系统代发问题。
- 运行记录测试：入口可见并能打开现有 `RunsCenter`。
- FinOps 加载测试：缓存更新失败保留数据；登录失效展示中文提示；组件部分失败不升级为全局失败。
- 图表测试：零值、单分类、多分类、稳定颜色、筛选联动、悬停/聚焦高亮和减少动态效果。
- 图表提示测试：展示正确口径和证据状态；没有真实缓存字段时不显示缓存命中结论。
- AI 浮框测试：按钮打开挂接聊天框且不改变 Dashboard 宽度；从指标打开时携带正确 `MetricContext`；清除上下文后不再发送指标信息。
- CSS/DOM 契约测试：同步状态和刷新按钮在同一容器内居中，不受标题说明选择器影响。

### 浏览器

- 桌面端和移动端首次进入截图。
- 强制刷新后立即检查完整导航，不允许运营管理或系统后出现。
- 进入运营管理时检查预取命中、加载骨架、同步状态和图表布局。
- 通过鼠标和键盘检查图表数据点动效、提示框和“问 AI”指标关联。
- 检查 AI 聊天框在桌面和移动端均从按钮附近展开，不以整块右侧抽屉挤压 Dashboard。
- 模拟 bootstrap、明细接口和登录失效三类错误。
- 启动自动分析，确认会话中无系统代发问题，运行记录中有对应任务。
- 从运行记录回到关联会话。

### 部署

- Python、Node、Vite 和 Playwright 全量回归通过。
- backend/web 先部署零流量候选 revision。
- 候选环境完成桌面、移动端、强制刷新、登录失效和真实接口验收。
- 保留当前生产 revision 作为回滚目标。
- 验收完成后才切换生产流量；治理执行开关继续保持关闭。

## 非目标

- 不部署或 fork OptScale。
- 不接入 Azure 实际账单。
- 不改变 MAF 编排、模型路由或生产治理动作边界。
- 不自动选择微软登录账户或绕过 Easy Auth。
- 不删除会话、运行或历史数据。
