# FinOps 趋势、ROI 回归证据与运营知识检索设计

日期：2026-08-11

## 目标

在不改变 MAF 业务内核、认证边界和治理执行开关的前提下，修正运营管理的三类展示缺陷：

1. 成本与调用趋势使用正常的零基线、自适应刻度、完整日期和进行中时间桶标识，不再让未完成当天看起来像完整日骤降。
2. 成本摘要改成紧凑的财务口径卡，集中展示估算成本、计价覆盖、已计价/未计价请求和操作入口。
3. ROI 增加“单位成本趋势回归校验”。回归和 MSE 只评价历史趋势模型的误差，不证明因果关系，也不把情景测算升级为已验证 ROI。
4. 运营 AI 将仓库内可审阅的中文内部方法文档作为检索知识源；知识只能解释定义、公式和判断边界，当前数值仍必须来自已授权请求证据。
5. 设置页、真实调用遥测与运行 Trace 使用同一模型路由事实，能够区分 DataForge 结果缓存、模型提供商 Token 缓存和入口治理覆盖。

## 关键设计

### 趋势图

- 服务端为每个小时/日桶返回 `bucket_status=complete|in_progress`。
- 前端以观测最大值生成 4–6 个常规刻度，保留零基线并将上界控制在观测最大值附近。
- 桌面端完整显示 `MM-DD`；空间不足时允许横向滚动，不使用省略号截断日期。
- 进行中桶采用斜纹/虚线视觉和“进行中”提示，数值仍按真实比例绘制。
- Token 栈使用“缓存输入、未缓存输入、未分类输入、输出、推理”互斥分层；缓存输入是输入 Token 的子集，不得与总输入重复叠加。
- 成本页按模型展示请求数、估算成本和 Token 构成，借鉴简洁的 FinOps 用量面板结构，但沿用 DataForge 浅色设计系统。

### ROI 回归校验

- 对每日“每次成功调用估算成本”做一元时间趋势回归。
- 前 70% 样本训练，后 30% 样本留出验证；至少需要 6 个有效日期。
- 返回 MSE、RMSE、MAE、R²、朴素基线 MSE、样本数与训练/验证数量。
- 价目估算参与的结果状态保持 `estimated`；样本不足返回 `insufficient_data`。
- 页面明确写出：误差指标衡量预测一致性，不等于已实现 ROI 或业务因果证据。
- 情景净收益或 ROI 比率不为正时，判定为“当前测算尚未达到正向回报”，不得输出具备投入价值的结论。

### 内部知识检索

- 知识源为 `backend/finops/data/knowledge/*.md` 的白名单文档。
- 文档按二级标题切块，使用有界的中英文关键词打分，最多返回 4 个片段。
- 模型上下文包含文档标题、章节、版本、摘要、适用边界和内部引用标签。
- 不向客户端暴露本地路径；不允许知识片段产生当前指标值、新证据或执行治理动作。
- `estimated` 是运营 AI 合法的数据状态；服务端必须接受该状态，前端不得向客户回显校验器 JSON。

### 模型路由与 Trace

- 设置首页“模型与生成”直接读取持久化工作区路由，显示有效模型、提供商、来源和策略版本；切换到 DeepSeek 后不再继续显示旧的 Azure 模型。
- 每次模型调用记录 `provider_type/provider_id/model_id`，用真实环境判断 `apim_governed` 或 `app_observed`，不把直连 DeepSeek 假报为入口治理。
- Trace 将 DataForge/Redis 结果缓存与提供商 Token 缓存分开显示，并保留只读 JSON 技术详情；Provider 未返回缓存 usage 时显示 `unavailable`，不推算命中。

## 验收

- 最大日成本约 23 USD 时，纵轴上界不再固定放大到 30 USD，日期不出现 `08-…`。
- 当前日若未结束，图例和 tooltip 明确标记“进行中”。
- 成本摘要在桌面和 390px 宽度无大片空白或操作按钮漂移。
- ROI 有数据时显示回归误差，无足够样本时诚实显示样本不足。
- 成本、缓存、ROI、风险问题分别检索到不同的内部知识章节，模型输入包含可读引用且不包含文件路径。
- 设置页选择 DeepSeek 后摘要同步显示 DeepSeek；实际 Trace 同步显示调用模型、提供商、入口治理和两层缓存证据。
- Python、Node、Vite、Playwright 和生产健康门禁通过后再切流量。
