# DataForge 运营管理 Demo 展示增强设计

## 目标

在不改变 MAF、工作区、数据、会话和产物等业务内核的前提下，把“运营管理”建设成面向 IT 与财务人员的完整展示面：

- 预算和管理员邮件提醒可在 Demo 环境直接配置与演示；
- 成本、缓存、调用、质量和 ROI 指标具有足够的数据差异与可视性；
- 风险、优化建议和证据下钻形成一一对应的可解释链路；
- 客户界面使用产品化语言，不直接暴露 APIM、Foundry 等底层服务名；
- 自动刷新降低到五分钟，同时保留进入页面预加载与手动刷新。

本次只向指定的“演示工作区”写入场景数据。前端不显示“演示数据”标识；后台必须保存内部来源和批次版本，用于幂等初始化、升级和清理，且不得影响其他工作区或租户。

## 方案选择

采用“数据库场景数据 + 确定性计算 + 按需 Agent 说明”的组合方案。

不采用纯前端静态填充，因为静态卡片无法保证筛选、图表、预算、ROI 和证据下钻相互一致；也不采用每次刷新都调用模型，因为其时延、成本和输出稳定性不适合演示。

运营指标、预算状态、ROI 公式和证据映射由服务端确定性计算。Agent 仅对已有结构化证据生成说明和建议，不参与数字生成，不在页面刷新时自动调用。

## 1. 演示工作区场景账本

### 1.1 初始化器

新增一个显式执行的幂等初始化器，输入只能是允许的演示工作区 ID。初始化器写入固定 `seed_batch` 和内部 `data_origin`，相同版本重复执行时更新或跳过既有记录，不重复累计。

公共 API 和前端不返回 `seed_batch`、`data_origin`。这些字段仅用于后台运维、验收和后续清理。

初始化器不得：

- 自动遍历或写入其他工作区；
- 保存真实身份、密钥、原始 provider response ID 或内部错误正文；
- 修改现有真实请求事实；
- 伪造 Azure 实际账单。

### 1.2 场景覆盖

场景数据至少覆盖：

- 4 个成员显示名称；
- 6 个 Agent；
- 4 个模型或 deployment；
- 最近 30 天的小时/日趋势；
- 明显不同的输入、输出、缓存输入、推理 Token；
- 成功、客户端错误、服务错误和慢请求；
- 已计价、未计价和部分计价请求；
- 缓存命中、未命中、绕过和不可用；
- 同工作区、同分析语义的 `miss → hit` 复用链路；
- 多条业务问题、最终可见回答、会话和运行关联；
- 预算接近阈值、达到阈值和正常成员；
- 已保存 ROI 情景与可复核业务结果；
- 成本突增、缓存不足、Token 异常、慢请求、失败率、未计价和预算临界等风险。

各维度数值必须具有明显差异，确保趋势图、排行、圆环、预算进度和 ROI 页面不会呈现等高或无区分度结果。

## 2. 预算与邮件提醒

### 2.1 权限与对象

预算按“成员显示名称”管理，不要求专用 `DataForge.FinOpsAdmin` Entra 应用角色，也不依赖 Microsoft Graph 成员查询。

操作仍必须满足：

- 已通过 Easy Auth 登录；
- 是当前演示工作区的 Owner 或 Admin；
- 写操作成功写入现有审计存储；
- 所有查询和修改都由服务端限制在当前工作区。

预算主体使用服务端生成的不透明引用，显示名称单独保存。不得以邮箱、Entra OID 或任意客户端资源 ID 作为公共预算主键。

### 2.2 预算模型

每个成员可配置：

- 月度预算金额，币种第一版固定为 USD；
- 两级阈值，默认 80% 和 95%；
- 启用或停用；
- 乐观并发 `base_revision`。

演示默认包含 `$200/月`、`80%/95%` 的成员预算，并提供接近 `$190` 的预警状态。

### 2.3 管理员邮件

管理员在设置页直接填写收件邮箱、发件显示名称、主题模板和正文模板。收件邮箱不需要绑定成员或 Entra 身份。

发送链路复用 Azure Communication Services Email：

1. 保存邮件设置；
2. 管理员执行测试邮件；
3. 测试邮件成功后才允许开启自动提醒；
4. 定时预算评估发现跨越阈值时写入提醒记录并发送；
5. 同一预算、月份、阈值和配置版本只发送一次；
6. 发送失败只保存安全错误类别，不保存服务密钥或完整错误正文。

## 3. 客户可见语言

客户界面不得直接显示底层 Azure 产品名称：

- `APIM 对账` → `请求对账`
- `APIM 覆盖率` → `网关治理覆盖率`
- `APIM 网关` → `统一网关`
- `APIM correlation` → `网关关联`
- `Foundry Trace` → `运行追踪`
- `Azure Monitor` → `云端监控`

后端内部字段名和采集器名称可以保持不变，避免破坏既有数据契约。底层产品信息只允许出现在管理员运维文档，不进入客户主要页面。

成本说明统一为“基于模型价目表的估算成本，不代表云厂商实际账单”。

## 4. 成本与缓存可视化

### 4.1 趋势图

趋势图使用真实零基线。纵轴上限根据当前可见数据计算为大于最大值的 `1/2/5 × 10ⁿ` 友好刻度，并显示至少四个刻度。柱高严格使用 `value / axisMax`，零值保持为零，不以固定最小高度伪造差异。

Token、调用、成本和 P95 分别计算自己的轴。成本小数使用足够精度，避免不同小额成本在显示层被舍入成相同值。

悬停或键盘聚焦时显示：

- 时间范围；
- 当前指标原始值；
- 输入、输出、缓存和推理 Token；
- 缓存命中、未命中、绕过数量；
- 相关运营事件数量。

### 4.2 成本页面

成本分析包含：

- 模型、Agent、成员、工作区成本排行；
- 成本趋势和周期对比；
- 模型与 Agent 成本结构；
- 缓存节省 Token；
- 按价目表估算的缓存节省成本；
- 未计价请求数量及进入模型价格设置的入口。

横向排行和圆环使用同一成本账本，不能由不同的前端示例数组独立生成。

### 4.3 缓存页面表达

缓存能力同时体现在：

- 总览命中率和 eligible 请求数；
- 命中、未命中、绕过、不可用分布；
- 趋势变化；
- Agent 和模型维度对比；
- 风险与优化建议；
- 请求证据的 `首次计算 / 复用结果 / 主动绕过 / 未记录` 状态。

缓存命中证据可以关联原始运行的不透明引用，但不得返回缓存键。

## 5. DataForge 自建 ROI

ROI 不依赖 Azure 或 Foundry 的 ROI 服务。DataForge 保存自己的 ROI 情景、结果事件和公式版本。

用户可配置：

- 每月节省人工小时；
- 人工小时价值；
- 每月避免损失或新增收益；
- 一次性实施成本；
- 每月固定运行成本；
- 当前模型估算成本；
- 评估周期。

服务端计算：

- 月度收益；
- 月度总成本；
- 月度净收益；
- ROI；
- 回收周期；
- 单次调用成本；
- 单个已验证结果成本。

公式和输入必须随 revision 保存。估算情景显示为“情景测算”，只有关联到已验证结果事件的数据才能显示为“可复核 ROI”。场景数据应同时提供完整情景和已验证结果，使页面能够展示理想能力。

## 6. 风险、优化与差异化证据

### 6.1 风险与建议

风险页按以下类型展示不同内容：

- 成本增长与预算压力；
- 缓存利用不足；
- Token 异常增长；
- P95 慢请求；
- 失败率上升；
- 未计价请求；
- 网关治理覆盖不足。

每条风险包含影响、置信度、样本、阈值、建议、预计节省或影响范围。Agent 分析卡负责解释“发生了什么、为什么值得关注、下一步怎么验证”，但不自动创建或执行生产治理动作。

### 6.2 证据选择

异常、优化机会和 Agent finding 都保存自己的 `evidence_refs`。点击“查看证据”时：

1. 优先读取条目直接引用的请求；
2. 若有多个引用，按该策略的相关度选择，例如慢请求选择延迟最高项、缓存问题选择 miss/bypassed、失败问题选择对应错误请求；
3. 无直接引用时才按当前筛选条件读取候选请求；
4. 不再对所有入口固定选择同一条最近请求。

### 6.3 会话内容

请求已关联会话时，证据抽屉展示：

- 友好的工作区、操作和时间名称；
- 业务问题的安全摘要；
- 最终可见回答的安全摘要；
- Agent、模型、Token、缓存、成本、延迟和错误类别；
- 处理阶段；
- 折叠的网关关联、运行 ID 和追踪链接。

仅使用已持久化的客户可见消息摘要，不采集 provider 原始响应、系统 prompt、密钥或内部错误正文。

## 7. 刷新与预加载

- 页面进入前继续预加载 bootstrap；
- 自动刷新从 60 秒调整为 5 分钟；
- 页面不可见时暂停；
- 页面重新可见时，只有缓存数据超过 5 分钟才刷新；
- 手动刷新立即执行；
- 自动刷新只读取已保存聚合，不触发模型或 Agent；
- 更新失败时保留上次成功数据，并显示轻量提示，不清空整页。

## 8. 接口与数据演进

优先扩展现有接口，不新增可接受任意脚本、资源 ID 或网关策略的公共写接口。

主要增量：

- 演示工作区幂等初始化命令；
- 工作区范围的预算主体和预算 CRUD；
- 手动管理员邮箱设置与测试邮件；
- ROI 情景参数和结果事件；
- anomaly、recommendation、opportunity 增加 `evidence_refs`；
- 请求列表支持安全的证据引用筛选；
- 趋势响应增加缓存分类和节省值；
- overview/bootstrap 聚合新增预算、缓存节省和 ROI 摘要。

数据库变更只能使用 additive migration。Redis 继续只做查询缓存，不保存预算、邮件、ROI 或证据事实。

## 9. 错误与安全边界

- 预算和邮件写入继续要求审计成功；
- 客户端不能指定 tenant；
- 所有预算和场景数据由服务端收窄到当前工作区；
- 收件邮箱仅在设置页按权限返回，不进入普通运营明细；
- 邮件密钥继续由托管身份或 Key Vault 提供；
- 自动治理动作和外部模型自动路由保持关闭；
- 演示数据初始化失败时按事务或幂等批次安全重试，不留下重复事实；
- 真实数据缺失时不得将 `null` 转换为观测到的零。

## 10. 测试与发布验收

### 后端

- 初始化器只写指定演示工作区；
- 重复初始化不重复累计；
- 预算 CRUD、revision 冲突、Owner/Admin 权限和审计失败；
- 手动收件邮箱保存、测试邮件门禁和阈值去重；
- ROI 公式、版本和证据状态；
- 风险类型与对应 `evidence_refs`；
- 缓存 miss→hit、节省 Token 与成本计算；
- 租户和工作区越权拒绝。

### 前端

- 客户页面不存在 APIM、Foundry、Azure Monitor 等服务名；
- 成本与 Token 数值不同时柱高明显不同；
- 纵轴为动态友好刻度且包含零基线；
- 缓存命中、未命中、绕过和节省指标可见；
- 每类风险打开不同证据；
- ROI 参数、公式结果和版本状态可理解；
- 自动刷新为五分钟且隐藏页面暂停；
- 预算和邮件配置在桌面端与移动端无溢出。

### 发布

1. Python、Node、Vite 和 Playwright 全量回归；
2. 生成桌面端和移动端截图；
3. additive SQL 连续执行两次；
4. backend/web 零流量候选；
5. 在候选环境执行一次演示工作区初始化；
6. 验证预算保存、测试邮件、缓存 miss→hit、差异化图表、不同证据和 ROI；
7. 记录镜像、revision、健康、日志和回滚点；
8. 经用户确认后再切换生产流量。

## 非目标

- Azure Cost Management 实际账单对账；
- 自动执行网关、模型路由或缓存策略；
- 将场景数据写入非演示工作区；
- 取消 Easy Auth 或允许匿名预算修改；
- 在页面刷新时实时调用模型；
- 采集或展示原始 prompt、provider 响应、身份 ID、密钥或内部错误正文。
